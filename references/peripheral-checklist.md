# 外设验收清单

> 每项给：**验收方法 / 通过判据 / 失败分支**。
> 一次只验一项，验不过就走失败分支，不要同时改多处。

---

## 1. 声卡输出（扬声器 + 3.5mm）

**验收**：扬声器出声 → 插 3.5mm 耳机出声 → 系统设置 → 声音 → 输出，设备可见且可切换

**通过判据**：两条输出路径都有声

**失败分支**
1. 换 `alc-layout-id`（在 `DeviceProperties → Pci(0x1f,0x3)` 下）
   - ★ 用 `alc-layout-id` 而不是 `layout-id`：前者优先级更高，可锁定布局、杜绝残留幽灵值
   - ❌ **绝不写进 boot-args**（AppleALC 只认 DeviceProperties）
2. 按 codec 逐个试官方 layout，每次改完 **Reset NVRAM** 再验
3. 确认 `AppleALC.kext` 完整（新版资源**内嵌二进制**，不要用"有没有 Resources/ 目录"判断文件是否损坏——
   那是错误判据。用 kext 体积 + Info.plist 里是否声明了你的 codec ID 判断）

---

## 2. 麦克风（内置 + 线控）

**验收**：系统设置 → 声音 → **输入**，选中内置麦克风，对着说话看**电平条是否跳动**

**通过判据**：电平有明显跳动

**失败分支**
1. 换 layout 再试（同上）
2. 确认耳机是 **4 极 CTIA TRRS**（3 极耳机不带麦）
3. ★ **若所有官方 layout 都「设备认得出、说话没电平」** → 不是 layout 选错，
   而是 **PinConfig / 节点拓扑层面**不匹配（codec 的输入节点没接进输入流）。
   走到这一步需 codec dump（Linux 下 `cat /proc/asound/card0/codec#0`）确认节点，再定制 PinConfigs。
   **成本较高，可权衡后只保留输出**。

> **真实案例**：Dell 5498 / ALC236 实测 13/15/21/28/54/99 六个 layout：
> 15 与 99 下扬声器+耳机都正常，但两个麦克风均无电平；21/28 整卡未被识别。
> 结论：**stock AppleALC 的 ALC236 布局没有能正确路由该机麦克风的**，继续换 layout 是死胡同。

---

## 3. 触控板

**验收**：移动、点击、双指滚动、多指手势

**判据**：指针与手势均正常

**失败分支**
| 现象 | 原因 / 处理 |
|---|---|
| 完全不动 | 总线选错（I2C 用 VoodooPS2 或反之）→ 回 `intake-questions.md` 批 4 确认 |
| 能动但无手势 | 驱动配置或 GPIO 引脚未配 |
| I2C 但无响应 | 缺 `SSDT-GPI0` / 需 `XOSI`；确认 GPIO 引脚号 |

---

## 4. 键盘

**验收**：全键位逐个敲一遍；**睡眠唤醒后再敲一遍**

**判据**：唤醒前后都正常

**失败分支**
| 现象 | 原因 / 处理 |
|---|---|
| **唤醒后部分键失灵**（典型：6/7/Y/U/H/J/N/M 这种成列的键） | ★ 键盘矩阵 **EC 防鬼影锁列**。这类通常**可自愈，不需要改 EFI**。处理：关机拔电源长按电源键 15s 做 EC 复位 + 清理键位。不要为此乱加驱动 |
| 唤醒后**所有**键失灵且不自愈 | 才考虑 PS2 控制器/EC 电源管理问题 |

> **判断 A/B 类的意义**：A 类（短暂、自愈）属固件行为，改 EFI 无效；
> B 类（持续、需重启）才需要动配置。误判会导致无谓的折腾。

---

## 5. 摄像头

**验收**：打开相机 App / 视频会议预览

**判据**：画面出现

**失败分支**：USB 摄像头通常免驱；内建（CSI）摄像头在黑苹果上多数无解。
先确认连接方式（批 4）再判断，别浪费时间。

---

## 6. USB 端口

**验收**：每个物理口都插一遍 U 盘/鼠标，确认可用；USB 3.0 口确认真的是 3.0 速率

**判据**：全部可用且速率正确

**失败分支**
1. 用 **USBToolBox** 做端口映射 → 加入 `UTBMap.kext`、**删除 `UTBDefault.kext`**
2. 单控制器端口超过 15 个才启用 `XhciPortLimit`（⚠️ 仅临时用途，映射完成后应移除）
3. 端口映射未完成前，常伴随**睡眠唤醒失败**与**端口速率异常**

---

## 7. 无线网卡 / 蓝牙

**验收**：Wi-Fi 能搜索并连接；**唤醒后是否自动重连**；蓝牙能配对

**判据**：连接 + 自动重连 + 蓝牙可用

**失败分支**
| 网卡 | 路线 |
|---|---|
| Intel | `itlwm`（配合 **Wi-Fi profile** 实现开机自连）或 `AirportItlwm`（按 macOS 版本选） |
| Broadcom 免驱 | 通常直连可用 |
| Broadcom 被新系统剔除 | 需 OCLP root patch |
| Realtek / MediaTek | 多数无解或**仅蓝牙可用**，建议换卡 |

> **唤醒后不自动连接**是独立问题（与能否连接无关），通常与 itlwm 的 profile 配置有关。

---

## 8. 电池

**验收**：电量百分比显示；离电续航合理；充放电状态正确

**判据**：显示正常 + 离电续航符合预期

**失败分支**
1. 先看 **有没有真睡过**（`pmset -g log` 的 `Total Sleep/Wakes`）——见 `power-management.md`
2. 再检查电池健康：`system_profiler SPPowerDataType | grep -i -E 'Cycle|Condition|Capacity'`
3. 最后才动 EC / 电池相关补丁

---

## 9. 内屏亮度

**验收**：系统设置 → 显示器，拖亮度条

**判据**：亮度可调且滑块生效

**失败分支**：面板是否为 eDP → 需要 `SSDT-PNLF`（见 `ssdt-audit.md`）

---

## 10. 外接显示器

**验收**：HDMI/DP 出画 + 音频（如支持）；在目标分辨率下做持续 UI 操作

**判据**：出画 + 高分辨率下不卡

**失败分支**
| 现象 | 处理 |
|---|---|
| 不出画 | 帧缓冲补丁 / 连接线类型 / 端口映射 |
| **2K/4K 下操作卡顿** | ★ **DVMT / `framebuffer-fbmem`**，见 `power-management.md` §四 |
| 想靠**开 HiDPI** 缓解卡顿 | ❌ **方向相反**：2K 面板上 HiDPI「看起来像 1280×720」实际仍渲染 2560×1440（像素不变，卡顿不变）；「看起来像 1920×1080」要渲染 3840×2160 再降采样（**更卡**）。唯一能降像素的是**切到 1080p 物理分辨率** |

---

## 回归测试总清单（改完 EFI 必跑）

```
□ 内屏亮度可调
□ 扬声器 + 耳机出声
□ 麦克风有电平（若在意）
□ 触控板移动 + 多指手势
□ 键盘全键位 + 唤醒后复验
□ 摄像头出画
□ 全部 USB 口可用
□ Wi-Fi 连接 + 唤醒后自动重连
□ 蓝牙配对
□ 电池显示 + 离电续航
□ ★ 盒盖睡眠 → 唤醒（不复现「提示重启」）
□ ★ 外接显示器（含目标分辨率下的流畅度）
```
